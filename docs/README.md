## 三条最该先知道的事

1. **`occupancy` 表是整个设计的核心。** 主稿第 3.1 节用一张表 + Postgres 排他约束，把"申请批了档期就不能被别人领走"从应用层检查变成数据库保证。这也是选 Postgres 而不是 SQLite 的唯一硬理由。
2. **所有数据库写入只经过 Rust 服务层。** 由此数据库约束的定位是**看门狗**（抓"有人绕过了服务层"的 bug），而不是正确性的唯一来源——例外是"错了不可撤销"的两处：编号唯一、档期互斥。
3. **并发控制只解决两类竞争**：状态流转（行锁）和档期占用（排他约束）。**描述性字段的编辑不设锁、不做在线状态、不做协同合并**——它是一次原子提交，后写覆盖，变更留痕。理由与适用范围见主稿 5.5。
